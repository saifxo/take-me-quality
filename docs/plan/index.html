Section 1

At a glance

A branded web app for the Take Me Quality (TMQ) programme. There are two roles to start with. QA reviewers listen to calls in the existing recordings portal and score them in a purpose-built form. Admins see every score as it lands, drill into any agent’s week, tune the rules, and manage accounts.

Keep
The TMQ framework exactly as marked today: 21 criteria, Yes / Partial / No / N/A, critical deductions, zero-tolerance auto-fail and the 90% KPI line. Section 3 has a live copy of the engine to check against.
Replace
Hand-typed rows, weekly files, drifting formulas and the unsaved =AI() column. Everything goes into one database with an audit trail.
Stack
Next.js (App Router, TypeScript), Tailwind + shadcn/ui in Take Me colours, Drizzle ORM, Better Auth, Vercel AI SDK with Gemini.
Database
PostgreSQL on Neon, London region, connected through the Vercel Marketplace, with a separate database branch for every preview deploy. Locally, Postgres 17 runs in Docker (already installed on this machine).
Hosting
Vercel, with functions pinned to London (lhr1) next to the database. The free Hobby plan is fine for the demo; production use by a company needs Pro.
Security
No public sign-up. Admins create every account, and role checks run on the server for every action. Customer numbers are masked, all changes are logged, and the Gemini key stays on the server.
First milestone
A demo your boss can click through. A reviewer pastes a call row, scores it in about a minute, and the admin dashboard, agent profile and AI summary update straight away.
Before we build

Eight questions in section 12 change the build. Each one has a default, so work can start now and your answers adjust it.

Section 2

How QA works today

QA runs on a weekly cycle. The reviewer opens the call-recordings portal, picks an agent and last week’s window (the screenshot shows Monday 31 Aug to Sunday 6 Sep 2026), plays calls and scores each one as a row on the Analysis sheet. The Overview sheet rolls those rows up per campaign and agent. A Google Sheets =AI() formula writes a coaching blurb per agent. The workbook is saved under the Monday’s date, e.g. 20260907 – Birmingham TMQ Scorecard, and next week starts from a fresh copy.

The __xludf.DUMMYFUNCTION wrappers inside the file show it was built in Google Sheets and exported to Excel, and =AI() is Sheets’ built-in Gemini function. The team already uses Gemini, so it is the natural model for the platform too.

What the current data says

  • 40 evaluations of 4 agents, 10 calls each, across 3 campaigns (Solihull 20, Birmingham 10, Nuneaton 10). There is one reviewer, and the review dates are 7 and 14 Sep 2026.
  • Every call scored 100%. Authentication, Booking Procedures and Airport are N/A on every row, and call type is “Booking” or blank.
  • Phone, call date/time and duration are empty in all 40 rows, so none of these scores can be traced back to its recording.

A wall of 100% is either an outstanding team or a lenient marker, and today nobody can tell which. The platform answers that with reviewer calibration (section 5) and with call-level traceability.

Section 3

The scoring rules, reverse-engineered

Every rule below comes from the formulas in Analysis!AE3 and AJ3:AM3 and from the sheet’s colour rules. The platform will reproduce them exactly and prove it with tests built from these same cases.

Points per answer

Across the 21 criteria (Analysis columns I–AC)

  • Yes = 1 · Partial = 0.5 · No = 0
  • N/A is left out of the count entirely
  • Score = (points − deductions) ÷ applicable criteria
  • Section scores use the same points, without deductions

Critical deductions

Taken off on top of losing the point

  • Confirming & Clarifying Names: No −2
  • Full Address Details: No −2
  • Authentication for Commercial Customers: No −2, Partial −1
  • Correct Booking Procedures: No −2, Partial −1
  • Airport Bookings: No −2, Partial −1

    Section 4

    What the sheet gets wrong

    Fourteen issues found by reading every formula, dropdown and colour rule in the workbook. This is the case for the platform in concrete terms. Each issue names the cells involved and the fix.

    1. 01

      Scores can’t be traced to their calls

      Phone Number, Date & Time and Duration are empty in all 40 rows. A disputed score can’t be replayed, and Avg AHT can’t be calculated.

      Fix: smart paste captures queue, extension, call time and duration. The caller number is stored masked.

      HighAnalysis C–E
    2. 02

      A skipped answer silently counts as No

      The divisor is COUNTIF(I:AC,"<>N/A"), which also counts blank cells. A forgotten dropdown lowers the score with no warning.

      Fix: every criterion needs an answer before submit, and N/A is an explicit choice.

      HighAnalysis AE
    3. 03

      Names are free text

      The only reviewer appears as two different people because one entry has a trailing space. A typo in an agent’s name splits their history the same way.

      Fix: agents and reviewers come from managed lists, and smart paste matches portal names to the roster.

      HighAnalysis B, G
    4. 04

      A new workbook every week

      Week-on-week trends mean copying between files. Overview blocks are fixed at 30 rows per campaign, and a new site means copying formulas.

      Fix: one database, any date range, unlimited sites and agents.

      HighWhole file
    5. 05

      No access control or audit trail

      Anyone with edit access can change past scores without a trace, and customer numbers would sit in a shared file.

      Fix: role-based access, an append-only audit log, masked numbers and a UK-hosted database.

      HighWhole file
    6. 06

      Avg AHT formula drifts down the column

      E7 compares against the campaign cell A5, but E8 points at A6, E9 at A7, and so on. Every agent after the first gets a wrong or blank AHT.

      Fix: one tested query instead of copied formulas.

      MediumOverview E8:E132
    7. 07

      Failed Reasons ranges drift too

      K7 reads Analysis!B2:B999, K8 starts at row 3, and by K71 it starts at row 66. Later agents silently skip early rows, and the lookup ignores campaign.

      Fix: reasons are linked records, not joined text.

      MediumOverview K7:K132
    8. 08

      Only one zero-tolerance issue per call

      HiHi is a single dropdown, so a call with two breaches records just one.

      Fix: multi-select, with a note for each issue.

      MediumAnalysis AD
    9. 09

      Sections divide by zero

      If every criterion in a section is N/A, the section summary shows #DIV/0!, which then breaks that agent’s averages.

      Fix: an all-N/A section is “not scored” and left out of averages.

      MediumAnalysis AJ:AM
    10. 10

      AI summaries run on empty input

      Agents with no comments get “Please provide the feedback you would like me to summarise…” as their coaching summary. The output changes on every recalculation and is never saved.

      Fix: AI runs only when there is enough data, and each result is saved with its date, model and prompt version.

      MediumOverview M
    11. 11

      Two rubric versions in one sheet

      The older 19-criterion rubric sits above the current 21-criterion one, and nothing records which version a call was marked under.

      Fix: versioned scorecards. Each evaluation keeps the version it was marked with.

      MediumTMQ Framework
    12. 12

      Scores can go negative

      Deductions have no floor. A call with every answer No scores −47.62% and matches no colour rule.

      Fix: floor at 0%, pending your answer to Q7.

      LowAnalysis AE
    13. 13

      Campaign average is an average of averages

      E5 averages the agent scores, so an agent with 2 calls counts as much as one with 10.

      Fix: call-weighted averages by default, agent-weighted available as an option.

      LowOverview E5
    14. 14

      The “N/a” campaign block shows errors

      The fourth block, meant for unassigned agents, shows #N/A when it is empty.

      Fix: an explicit “Unassigned” filter instead.

      LowOverview A101:M132

    Review Studio: the reviewer’s form

    Most of a reviewer’s time goes on listening, so the form must never slow them down. It fits on one screen, works from the keyboard, and is forgiving of mistakes.

    • Start from the portal. Paste one row or ten from the recordings table. Each becomes a queued call with agent, site, time, duration and a masked number already filled in. Unknown agents are flagged for an admin to confirm.
    • Call type sets sensible defaults. Choosing Booking, Airport, Account, Enquiry, Complaint or Cancellation pre-selects N/A where a criterion can’t apply. For example, Airport is N/A unless it’s an airport job.
    • One tap per criterion, with keys 1–4 for Yes / Partial / No / N/A, arrow keys to move, and Ctrl+Enter to submit.
    • The rubric beside the question. An info button opens that criterion’s Yes / Partial / No descriptions and marker notes, so there’s no switching to another sheet.
    • Partial or No asks what happened. The reviewer adds a short note and an optional timestamp such as 01:12, which makes the feedback specific enough to coach from.
    • Zero-tolerance panel set apart in red. It allows several issues, needs a note, and warns “this call will score 0%”.
    • Live score, band and deductions, exactly as in the section 3 demo.
    • Autosaved drafts, a warning if the same call was already reviewed, and “Next call” to work through the queue.

    Playbook

    The rubric, the zero-tolerance list and the marker notes become a searchable guide, linked from every question in the form and printable in place of the Print Version sheet. It includes the greeting rule: approved names are “Take Me” and “Great Barr”; not approved are “Tower”, “Taxi First”, “Take Me Taxi(s)” and “Take Me Cab”. Take Me grows by buying local firms, so old brand names are a live risk and deserve a prominent place. The paraphrase rule, “Location + Street or Area”, and examples of good calls sit alongside.

    Admin dashboard

    Filters sit in one row at the top: week (default: last full week, compared with the week before), site, team, reviewer and call type. Every number links through to the calls behind it.

    WidgetThe question it answers

    Weekly trend by siteAre Solihull, Birmingham and Nuneaton improving? Twelve weeks, with the 90% KPI line drawn in.
    Section performanceWhich part of the call is weakest: greeting, booking, handling or closure?
    Criteria heatmapWhere are the training needs? All 21 criteria by agent or site, e.g. a whole team asking callers to spell well-known places.
    Zero-tolerance logWhich breaches happened, where and when? Each one opens its call.

    Reviewer calibrationIs each reviewer marking to the same standard? Each reviewer’s average against the team’s, plus volume and time per review.

    Agent profile

    The page a manager opens before a one-to-one. It shows current score and band, a weekly trend, section scores against the team average, strongest and weakest criteria, any zero-tolerance history, AHT over time, and every evaluation with the reviewer’s notes. A dated history of AI coaching summaries sits alongside, and Export for 1:1 produces a clean PDF.

    Metrics dictionary

    One definition per number, used by every chart and export. A week runs Monday 00:00 to Sunday 23:59 UK time and is decided by call date, not review date (Q4).

    MetricDefinition
    QC scoreMean of evaluation scores in the period, weighted by call
    KPI attainmentEvaluations above 90% ÷ all evaluations
    Below-KPI shareEvaluations at 90% or under ÷ all evaluations (the sheet’s “Below KPI Score”)
    Auto-fail rateEvaluations with at least one zero-tolerance issue ÷ all evaluations
    Perfect rateEvaluations at exactly 100% ÷ all evaluations
    Section scoreMean of section scores where that section was scored (no deductions)
    Criterion pass rateYes ÷ (Yes + Partial + No) for one criterion
    Average AHTMean duration of the evaluated calls
    CoverageAgents who reached the weekly review target ÷ active agents
    Reviewer varianceA reviewer’s mean score minus the team mean on comparable calls

    Guardrails

    • The key never reaches the browser. It lives in server environment variables, and every request goes browser → our server → Gemini.
    • Send the minimum. Customer numbers, addresses and names are never sent. Agents are referred to by first name or ID.
    • Use a paid, billing-enabled Gemini key. Google’s terms allow it to use content sent through unpaid tiers to improve its products, which is not acceptable for staff performance data.
    • Notes are data, not instructions. Prompt templates keep reviewer text separate from instructions, and every output is checked against a schema and a length limit.
    • Everything is saved. Each output is stored with its model, prompt version, input fingerprint and requester. Identical inputs reuse the saved answer, and daily per-user quotas cap spend.
    • Labelled and editable. Output is marked “AI-generated”, admins can edit prompt templates (starting from today’s =AI() prompt), and the model name is a setting, not code.

    Section 9

    Security and privacy

    • No public sign-up; admin-created accounts; temporary password changed at first sign-in; bcrypt hashes.
    • httpOnly, Secure, SameSite session cookies; idle timeout; revoke on disable; login rate limiting.
    • Role checks in the server data layer for every action; Zod validation; parameterised SQL.
    • Caller numbers masked on entry and only a keyed hash stored; data hosted in London.
    • Append-only audit log; soft delete; security headers (CSP, HSTS, frame-ancestors none).
    • Gemini key server-side only; no customer data sent; outputs saved and labelled.

    Section 11

    What you might be missing

    • Calibration: reviewers marking the same call to align standards.
    • Disputes and acknowledgement: agents or leaders can challenge a score.
    • Coaching loop: a below-KPI or breach creates a follow-up task.
    • Sampling plan: a weekly target and a mix of short and long calls.
    • Time zones: store UTC, show UK time, weeks by call date.
    • Retention: how long call identifiers and scores are kept.
